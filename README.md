# Battery Check

Монитор энергопотребления ноутбука в реальном времени (Windows 10/11). Две версии на общем коде: окно с графиком и консольная. Обе пишут CSV-лог для последующего анализа здоровья батареи.

## Установка

Скачайте `BatteryCheckSetup-<версия>.exe` из [Releases](https://github.com/nik-agilefox/BatteryCheck/releases/latest) и запустите. Установщик ставит программу только для текущего пользователя, без прав администратора: в `%LOCALAPPDATA%\Programs\BatteryCheck` (логи — в подпапке `logs`), с ярлыком в меню «Пуск» и пунктом в «Установленных приложениях» для удаления. Exe не подписан, поэтому при первом запуске Windows SmartScreen покажет предупреждение: «Подробнее» → «Выполнить в любом случае».

Тихая установка и удаление: `BatteryCheckSetup.exe /silent`, `uninstall.exe /uninstall /silent` (данные сохраняются).

**Обновление.** Кнопка «Check updates» внизу окна (программа проверяет и сама — при запуске и раз в 6 часов). Если на GitHub вышел релиз новее, кнопка превращается в «Update to <версия>»: программа скачивает архив релиза, сверяет размер и SHA-256, подменяет свои файлы и перезапускается. Логи и настройки не трогаются. Сборка из папки с исходниками релизом не обновляется — только через git и `build.cmd`.

**Выпуск версии** (для разработчика): `powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Version 1.0.1 -Notes "что изменилось"` — номер версии в `src\Core\AppInfo.cs`, тесты, сборка, архив и установщик в `dist\`, коммит с тегом и релиз на GitHub.

## Сборка и запуск

Ничего устанавливать не нужно: собирается компилятором C#, который входит в .NET Framework 4.8 (есть в каждой Windows 10/11).

```
build.cmd
bin\BatteryCheckGui.exe     окно
bin\BatteryCheck.exe        консоль
bin\BatteryCheckSetup.exe   установщик (оба exe внутри)
```

Права администратора не требуются.

## Окно

Плитки (потребление, заряд, оставшееся время, здоровье батареи), график мощности за 10 минут (батарея, процессор, видеокарта) с подсказкой при наведении, таблица компонентов, данные батареи и сессия разряда с кнопкой «Сбросить». Тема светлая или тёмная по настройке Windows, переключается на лету.

**Язык интерфейса** — английский (по умолчанию) или украинский: переключатель **EN | UA** в правом верхнем углу, слева от состояния питания. Окно перестраивается сразу, данные графика и журналы сохраняются; меню и подсказка значка в трее тоже переводятся. Выбор запоминается (`HKCU\Software\BatteryCheck\Language` = `en` / `ua`) и действует и для консольной версии. Числа форматируются по языку: `23.4 W` / `23,4 Вт`. Названия элементов окна ниже в этом описании даны по смыслу.

| Параметр | Что делает |
|---|---|
| `--background` | Запуститься сразу в трее, без окна (так программа стартует при автозапуске) |
| `--exit` | Закрыть уже работающую копию (как «Выход» в меню значка) |
| `--no-gpu` | Запустить с выключенным опросом NVIDIA (переключается и кнопкой в окне) |
| `--no-log` | Не писать лог |
| `--theme light` / `--theme dark` | Задать тему вместо системной |

Нагрузка: около 3 % одного ядра, пока окно открыто (перерисовка раз в секунду), и практически ноль в трее или свёрнутом виде. Опрос и лог при этом продолжаются.

### Плитка мощности и мини-график

- **От батареи** — измеренный разряд; справа мини-график за 5 минут с автоматической шкалой.
- **От сети** — «От блока питания ≈ N Вт» и две строки: сколько уходит **в аккумулятор** (измерено) и **на работу** ноутбука. На мини-графике за 5 минут линия — вся мощность от блока, зелёная заливка — часть, уходящая в аккумулятор, верх графика (пунктир) — мощность зарядного устройства; справа сверху — доля от неё. При заданной мощности зарядного линия желтеет от 80 % и краснеет от 95 %.

Windows не измеряет вход от блока питания и не сообщает его мощность (стандартный драйвер AC-адаптера отдаёт только «подключён», данные USB-C закрыты, методы WMI Acer не документированы). Поэтому:
- **вход от блока — оценка**: заряд аккумулятора + процессор + видеокарта + «остальное» (экран, плата, накопитель). «Остальное» берётся последним измеренным при работе от батареи (запоминается; при первом запуске — медиана из CSV-логов). Подсказка у мини-графика раскладывает оценку на слагаемые;
- **мощность зарядного** — щелчок по мини-графику: точное значение из ряда 65–330 Вт (указано на блоке питания) или «Оценивать автоматически». Автоматическая оценка — нижняя граница: ближайшая стандартная мощность не меньше наибольшего наблюдённого входа (сглаженного за 10 с). Под обычной нагрузкой она ниже настоящей, поэтому доля завышена и предупреждающие цвета отключены.

### Простой этой машины и «лишние ватты»

От батареи во второй строке плитки мощности — **простой этой машины** и на сколько сейчас расход выше него: «простой 11,2 Вт · +8,3 Вт лишних». В подсказке — разбор:
- **видеокарта не спит** — её мощность (в тихие минуты она спит, её простой — 0);
- **процессор выше простоя** — × 1,75: каждый ватт процессора добавляет ~0,75 Вт в «остальное» (питание, память);
- **экран выше простоя** — по замеру экрана;
- **прочее** — остаток.

Простой берётся из логов за 14 дней, отдельно его мерить не нужно. **Тихая минута** — все замеры минуты от батареи, дискретная видеокарта спит, ввода с клавиатуры и мыши не было ≥ 60 с (колонка `idle_s`; в логах до её появления — только по видеокарте), замеров хотя бы 3. Простой — медианы по самым тихим 20 % тихих минут (общий расход, процессор, «остальное», экран — по одному набору минут). Нужно хотя бы 20 тихих минут, до этого в плитке — сколько уже собрано: «idle: collecting N/20 quiet min». Пересчёт — при запуске и раз в 30 минут в фоне; поминутные итоги законченных логов кэшируются, заново разбирается только текущий.

### Проверка «до / после»

Вверху вкладки «Советы» — карточка «Проверить изменение»: что вы меняете (например, «закрыл PredatorSense») и «Начать»; у каждого совета есть кнопка «Проверить» с его названием.

1. **«До»** — 8 тихих минут. Если они только что были (последние минуты подряд, свежие), берутся сразу из учёта, ждать не нужно.
2. Вы делаете изменение и нажимаете **«Готово»**.
3. **«После»** — ещё 8 тихих минут.
4. Итог: «−2,3 ± 0,6 Вт · 19,5 → 17,2 Вт · ≈ +35 мин» и подробности — процессор, доля времени, когда дискретная видеокарта не спит, её пробуждений в час, число минут.

Сравниваются только **сопоставимые минуты**: все замеры минуты — разряд, ввода с клавиатуры и мыши не было ≥ 60 с, яркость одна, окно программы на экране (иначе меняются опрос и отрисовка), не идёт замер экрана. Поминутный учёт идёт всегда (последние 30 минут). Погрешность — стандартные ошибки средних по минутам, сложенные квадратично; эффект засчитывается, если разница больше двух погрешностей и не меньше 0,3 Вт, иначе — «разницы не найдено». На время проверки экран не гаснет (`SetThreadExecutionState`), после — снова по настройкам Windows. Нужна работа от батареи; за 30 минут без 5 тихих минут на фазу проверка прекращается. Итоги — в `logs\experiments.csv`, последние пять — под карточкой.

### Профиль «На батарее»

Карточка во вкладке «Советы», под проверкой «до / после»:
- **Яркость на батарее** — «не менять» или 30–70 %. Через 5 с после отключения зарядки (дребезг разъёма — не повод) яркость снижается до выбранной, если сейчас она выше; при подключении возвращается прежняя — **только если вы её тем временем не меняли** (иначе остаётся ваша, и это записывается в журнал). Перед сменой — подсказка журналу пробуждений: смена яркости будит NVIDIA.
- **Частота экрана на батарее** — наименьшая, которую драйвер предлагает в текущем разрешении; меняется без записи в реестр (`ChangeDisplaySettingsEx` с флагом 0 после проверки `CDS_TEST`), откат — режим из реестра, а после сбоя его вернёт и перезагрузка. Если частота у экрана одна (у этого ноутбука — только 240 Гц), вместо переключателя — «экран поддерживает только N Гц».
- **Режим питания Windows от батареи** — те же четыре варианта, что в Параметрах → Система → Питание (`PowerSetUserConfiguredDCPowerMode`, без прав администратора). Это постоянная настройка Windows, меняется сразу и при подключении зарядки не откатывается.

- **Режим эффективности на батарее** — список программ (добавить: правый клик по программе в таблице «Процессы» или «Кто тратил батарею», кнопка у совета о программе; убрать — «×» в карточке). При отключении зарядки им включается то же, что «Режим эффективности» в диспетчере задач: EcoQoS (`SetProcessInformation`, `ProcessPowerThrottling`) — Windows держит процесс на энергоэффективных ядрах при низкой частоте — и низший приоритет; при подключении снимается. Новые процессы тех же программ (вкладки браузера, перезапуски) подхватываются раз в 30 с. Без прав администратора — только для процессов этого пользователя: службы (SYSTEM, например службы Acer) и программы от администратора Windows изменить не даст — программа так и скажет. Режим снижает нагрузку на процессор, но **не убирает пробуждения видеокарты**: программа, которая её опрашивает, продолжит опрашивать.

Что изменено — в строке состояния («Действует: яркость 80 → 50 %») с кнопкой «Отменить сейчас» (до следующего отключения зарядки профиль не применяется снова). Все изменения — в `logs\actions.csv` (время, действие, было, стало, кто: профиль или вы), последние пять — под карточкой. Состояние профиля хранится в реестре: если программа упала, при следующем запуске от сети всё откатится.

### Уведомления

Только при работе от батареи, у значка в трее (в Windows 11 — как обычное уведомление); щелчок открывает окно. Каждый тип — не чаще раза в 30 минут, во время замера экрана — не показываются. Выключатель — «Уведомления о батарее» в меню значка.

| Когда | Что в уведомлении |
|---|---|
| 10 минут подряд без ввода с клавиатуры и мыши, а расход больше 1,5 простоя этой машины | расход, простой и вероятный виновник: дискретная видеокарта (если не спала больше половины времени — с причиной из журнала пробуждений), иначе программа с наибольшим расходом (если идёт сбор по процессам), иначе процессор против его простоя |
| Дискретная видеокарта не спит 5 минут, а её никто не нагружает больше чем на 30 % (игра — не повод) | сколько минут, её мощность и причина пробуждения |
| Внешний монитор подключён к дискретной видеокарте | раз за разряд |
| Заряд 20 % и 10 % | оставшееся время при текущей мощности; по разу за разряд (запуск уже на 8 % — одно уведомление) |

Логика — в `src\Core\Notifier.cs`; учёт идёт и при выключенных уведомлениях.

### Правила советов и своя норма

Правила — в `src\Core\rules.json` (встраивается в программу при сборке):
- **категории программ** — название на двух языках, ориентир фонового потребления, совет, имена процессов и префиксы: мессенджеры, браузеры, веб-приложения, лаунчеры игр, утилиты производителей, мониторы железа, обслуживание Windows, композитор окон, система;
- **производители** — Acer, Lenovo, ASUS, Dell, HP, MSI, Razer, Samsung: как узнать по строке из BIOS (`HKLM\HARDWARE\DESCRIPTION\System\BIOS`, без прав администратора), их утилиты и префиксы процессов, подсказка про тихий режим в их программе (в совете про режим питания);
- **программы, которые опрашивают видеокарту** — подозреваемые в совете про пробуждения NVIDIA.

Свои правила — `rules.user.json` рядом с папкой `logs` (в формате `rules.json`): категория или производитель с тем же `id` заменяются, новые добавляются, `gpu_pollers` объединяются. Ошибка в файле не ломает советы — работают встроенные правила, а ошибка показывается во вкладке. Списки утилит производителей неполные — их удобно дополнять своим файлом.

**Своя норма.** «Выше обычного» сравнивается прежде всего с тем, сколько **эта программа на этом ноутбуке** обычно тратит в фоне: фоновые Вт·ч за день ÷ часы от батареи в тот день, медиана по дням за 30 дней до текущей недели, когда программа работала и от батареи было хотя бы 15 минут; нужно хотя бы 3 таких дня. Совет — если на этой неделе больше 1,5 нормы и больше нормы + 0,3 Вт («Telegram в фоне тратит 1,2 Вт — обычно на этом ноутбуке 0,4 Вт»). Пока своей нормы нет — сравнение с ориентиром категории (эвристика). Колонка «обычно» в таблице показывает свою норму («≈ 0,4 Вт (ваша)») или ориентир категории («до 1,0 Вт»).

### Сон ядер и системный таймер

В карточке «Компоненты» под таблицей: **ядра в самом глубоком сне** — доля времени (счётчик Windows «% C3 Time», сглажено за 10 с) и **системный таймер** — как часто «тикает» Windows (15,6 мс — норма; 1 мс и меньше — какая-то программа просит будить систему тысячу раз в секунду, ⚠). Оба пишутся в лог (`cpu_c3_pct`, `timer_ms`); при таймере ≤ 2 мс от батареи — совет. Режим эффективности (и «Максимальная экономия») заодно велит Windows игнорировать запросы таймера этих программ. Какая программа держит таймер, Windows без прав администратора не сообщает (это показывает `powercfg /energy`).

### Пока вы не работаете

Во вкладке «Советы» — средняя мощность программ в **тихие минуты**: от батареи и без ввода с клавиатуры и мыши всю минуту (из `battery_*.csv`) — по минутному журналу `process_energy_*.csv` за те же минуты. Программа от 0,5 Вт в такие минуты — совет (части Windows вроде System и dwm — нет).

### Максимальная экономия

Кнопка в заголовке окна, слева от EN | UA. Меняет **только значения для батареи** активной схемы питания (без прав администратора, если схема пользовательская): ускорение процессора выключено (нет всплесков частоты — главный источник нагрева), EPP = 100 для P- и E-ядер, экономия энергии Windows — при любом заряде. Повторное нажатие возвращает прежние значения, кроме изменённых вами. От батареи все **фоновые программы** переводятся в режим эффективности (раз в 10 с), кроме активного окна — всех процессов той же программы и их потомков (переключились — режим снимается сразу), Battery Check и исключений `efficiency_exclude` в `rules.json` (оболочка Windows, плееры, звонки, ассистенты). Процессы, которые уже были в режиме эффективности, не трогаются. При подключении зарядки, выключении кнопки или выходе всё снимается; в журнале — одна запись на включение и одна на выключение.

### Вкладка «Оптимизация»

Сторонние службы Windows — не Microsoft и не внутри `svchost` (отбор по производителю файла: службы производителей ставятся и в `System32`, и в `DriverStore`); службы защиты не показываются. По каждой: процесс, состояние, **средний расход от батареи** по `process_energy_*.csv` за 7 дней и **сейчас** (пока вкладка открыта, идёт замер по процессам), ⚑ — процесс из списка известных «будильников» видеокарты (`gpu_pollers` в `rules.json`). Тяжёлые от батареи — вверху.

Battery Check службы **не останавливает** (нужны права администратора): «Открыть Службы» → правый клик → Остановить (после перезагрузки служба запустится снова). «Проверить» у службы — проверка «до / после» с её названием: программа скажет, когда остановить службу, и измерит разницу.

### Вкладка «Советы»

Рекомендации по автономности на встроенных правилах (без сети и внешних сервисов) за последние 7 дней работы от батареи, по убыванию выгоды; у каждой — оценка экономии в ваттах, прибавка автономности от полной батареи в минутах и основание («замер», «оценка по логам», «типичное значение»):
- **программы с нетипичным фоновым потреблением** — сравнение со справочником ориентиров по категориям (мессенджер до ~0,3 Вт, браузер до ~1 Вт, веб-приложение до ~0,5 Вт, лаунчер игр и утилита производителя до ~0,2 Вт и т. д.); «выше обычного» — больше полутора ориентиров и больше ориентира на 0,2 Вт. Отдельно отмечается, если в фоне работает видеокарта;
- **пробуждения NVIDIA** — по журналу пробуждений (только при работе от батареи), с вероятными виновниками среди запущенных программ;
- **экран** — частота обновления выше 60 Гц; на OLED по замеру экрана: высокая яркость при светлом содержимом и много белого на экране;
- **система** — режим питания Windows для работы от батареи, внешний монитор на NVIDIA; предупреждение, если данных мало (меньше 15 мин).

Ниже — таблица «Кто тратил батарею»: всего, доля, фоновое потребление в среднем, ориентир для категории и отметка «выше обычного».

Сбор включается и выключается кнопкой «Анализ процессов» внизу слева (выбор запоминается). Данные о программах собираются в фоне при работе от батареи: снимок процессов раз в 10 с (~0,2 % одного ядра), энергия каждого процесса (всего, в активном окне, на видеокарты) раз в минуту пишется в `logs\process_energy_ГГГГММДД.csv`. От сети сбор не идёт. Энергия программ — оценка (по тактам процессора и загрузке видеокарт), ориентиры по категориям — эвристика, а не замеры.

### Вкладка «История»

Третья вкладка рядом с «Компоненты | Процессы»: прошлые разряды — от отключения зарядки до её подключения — по CSV-логам программы. По каждому: дата и время, **сколько ноутбук проработал от батареи**, **диапазон заряда** (полоска на шкале 0–100 % и «100 → 57 %»), израсходованная энергия, средняя мощность и **полный разряд** — сколько ноутбук проработал бы от 100 % до 0 % при этой средней мощности (для разрядов от 10 мин). Сверху — сводка: число разрядов, общее время от батареи, средняя мощность, типичная автономность (медиана прогнозов).

Логи разных версий и одновременно работавших копий сливаются по времени. Пропуск больше 60 с внутри разряда — сон или программа не была запущена: это время не входит в «от батареи» и видно в подсказке; пропуск больше 12 ч — новый разряд. Разряды короче 2 мин или меньше 1 % не показываются. Разбор — в фоне при открытии вкладки и раз в минуту, пока она открыта (лог сбрасывается на диск раз в минуту).

**Честность индикатора заряда** — колонка «индикатор» и вывод в сводке. Это отношение энергии, которую батарея отдала по счётчику (мощность × время), к убыли остатка, от которого Windows считает проценты, — на одних и тех же непрерывных участках (без сна и пропусков). 1,00 — проценты соответствуют отданной энергии; 0,80 — проценты падают на 25 % быстрее, и 0 % наступит, когда батарея отдаст лишь 80 % обещанного (реальная полезная ёмкость = полная × отношение). Отношение считается и по полосам заряда 0–20 … 80–100 % (в подсказке у значения): на низком заряде напряжение ниже и на процент приходится меньше энергии, поэтому со временем сравнивается полоса с той же полосой. Вывод:
- **честный** — по разрядам от ~7 % (5 Вт·ч);
- **⚠ падают быстрее** — в 2 из 3 последних разрядов отношение ниже 0,92;
- **⚠ дрейф** — в какой-то полосе 3 последних разряда подряд на 7 % ниже своей обычной величины (медиана более ранних, нужно хотя бы 6 разрядов);
- **прыжки** (↯ в колонке) — остаток упал на 3 % и больше между соседними замерами, а энергии ушло втрое меньше.

При предупреждении — подсказка про калибровку (полный заряд → разряд до выключения → полный заряд) или износ ячеек.

### Масштаб и история

Окно хранит историю за **10 часов** (пока программа работает; в фоне точки раз в 10 с, при открытом окне — раз в секунду).

- **Период** — переключатель в заголовке графика: 1 мин, 5 мин, 10 мин, 30 мин, 1 ч, 3 ч, 10 ч (запоминается).
- **Колесо мыши** над графиком — приблизить или отдалить на один шаг; при сдвинутом графике — относительно точки под курсором.
- **Перетаскивание** — сдвиг в прошлое. График перестаёт следовать за новыми данными, на оси вместо «−2 мин» — часы.
- **«К текущему»** или **двойной щелчок** — вернуться к последним данным.

В режиме «Процессы» лидеры и средние в таблице считаются по видимому периоду. Когда точек больше, чем пикселей, в каждом столбце пикселей остаются минимум и максимум — пики не теряются. На длинных периодах график перерисовывается реже: не чаще раза в (период / 600), то есть каждую секунду на 10 минутах и раз в минуту на 10 часах.

### Уровень заряда на фоне графика

В обоих режимах за линиями мощности идёт еле заметная нейтральная заливка — уровень заряда батареи. У неё своя шкала: верх области графика — 100 %, низ — 0 %. Отдельной оси нет намеренно, чтобы проценты не путали с ваттами: шкала названа в легенде («Заряд 78 % · фон, шкала 0–100 %»), точное значение — в подсказке при наведении, отдельной строкой.

### Режим графика «Процессы»

Переключатель «Компоненты | Процессы» над графиком (выбор запоминается). В режиме «Процессы» график показывает 5 процессов с наибольшей средней мощностью за 10 минут и линию «Остальные процессы», а левая нижняя карточка — таблицу: мощность сейчас и в среднем, загрузку ЦП и ГП. Процессы с одним именем суммируются. Цвет закреплён за процессом, а не за местом в рейтинге.

Windows не измеряет мощность процессов, поэтому это **оценка**:
- мощность ядер процессора (RAPL PP0) делится по тактам, израсходованным каждым процессом;
- встроенная графика (RAPL PP1) и NVIDIA (NVML) — по загрузке их движков процессом (счётчики «GPU Engine»), адаптеры определяются через DXGI;
- «Не распределено» — то, что процессам не принадлежит: от батареи это экран, плата, накопитель, сеть и общая часть процессора; от сети — только общая часть процессора.

Сбор идёт раз в секунду и только пока этот режим открыт на экране: замер стоит около 20 мс процессора (`NtQuerySystemInformation` собирает сведения о каждом потоке системы), то есть ≈2 % одного ядра; в фоне и в режиме «Компоненты» — ноль. Дешёвые способы через `OpenProcess` не видят системные процессы (`dwm`, `csrss`, службы) без прав администратора.

### Фоновый режим и значок в трее

Крестик окна прячет программу в трей, выход — через меню значка. Повторный запуск не создаёт вторую копию, а открывает окно работающей.

На значке — только цветные цифры, без плашки (число на 60 % высоты, под ним мелкая растянутая подпись WATT): полная текущая мощность в ваттах — при работе от батареи измеренный разряд, от сети оценка входа от блока питания (как в плитке; «AC» — только пока оценки нет). Цифры вписаны почти на всю высоту значка (по ширине сужаются не больше чем на 20 %). Цвет: синий — от батареи, жёлтый — заряд ниже 20 %, красный — ниже 10 %, зелёный — заряжается, серый — от сети. Оттенки подбираются под тему панели задач (она отдельна от темы приложений): на светлой панели — тёмные, на тёмной — светлые. Подсказка при наведении: мощность, заряд, оставшееся время. Пока курсор над значком, значок и подсказка не обновляются: WinForms при каждом изменении значка заново отправляет подсказку, и открытая подсказка мерцала. Меню: открыть окно, сбросить сессию, опрос NVIDIA, «Запускать вместе с Windows» (запись в `HKCU\...\Run`, без прав администратора), выход.

Частота опроса подстраивается под режим:

| Режим | Интервал |
|---|---|
| Окно на экране | 1 с |
| В фоне, от батареи | 10 с |
| В фоне, заряд | 10 с |
| В фоне, от сети без заряда | 10 с |
| В фоне от батареи, пока NVIDIA не спит | 2 с |

Смена источника питания и пробуждение после сна вызывают замер сразу, по событию Windows, не дожидаясь паузы.

После сна или гибернации при работе от батареи программа показывает в карточке сессии длительность сна и потраченную энергию; подсказка у значения — средний расход во сне.

`tools\screenshot.ps1` запускает окно и сохраняет его снимок. Нужен для проверки вёрстки.

### Воспроизведение логов

`BatteryCheck.exe --replay logs` прогоняет записанные логи через ту же логику, что и живой опрос (сглаживание, сессия разряда, «остальное», прогноз), и печатает итог: время от батареи, энергию двумя способами, список разрядов с честностью индикатора и общий вывод. Без `--speed` — сразу итог (15 тыс. замеров — меньше секунды), с `--speed 60` — экран консоли в 60 раз быстрее реального времени. Логи старых версий читаются по заголовку; несколько файлов сливаются по времени. Нужен, чтобы проверять расчёты на настоящих данных без железа, в том числе на логах с других ноутбуков.

## Источники данных

| Источник | Что даёт | Ограничения |
|---|---|---|
| Драйвер батареи (`IOCTL_BATTERY_QUERY_*`) | Паспортная и полная ёмкость, циклы, остаток, напряжение, мощность заряда/разряда | Мощность есть только при работе от батареи или при заряде |
| Счётчики Windows «Energy Meter» (RAPL) | Мощность процессора: весь чип, ядра, встроенная графика | Только процессор |
| Диспетчер устройств (`SPDRP_DEVICE_POWER_DATA`) | Состояние питания видеокарты NVIDIA: D0 — работает, D3 — спит | — |
| NVML (`nvml.dll` из драйвера NVIDIA) | Мощность, загрузка и P-state дискретной видеокарты | Только NVIDIA. **Будит спящую видеокарту** |
| `EnumDisplayDevices` | Число подключённых экранов и сколько из них выводится через NVIDIA | Пересчитывается раз в 10 с |

«Остальное» = мощность батареи − процессор − видеокарта (сглажено за 10 с). Это экран, SSD, сеть, вентиляторы, плата и потери преобразователей.

На графике и в таблице «Компоненты» слагаемые не пересекаются: **процессор (без графики)** = весь чип (RAPL PKG) − встроенная графика; **встроенная графика** (RAPL PP1) — отдельной линией; **дискретная NVIDIA** (NVML); **остальное** — отдельной линией; **всего** — их сумма. От батареи «всего» — измеренный разряд, а «остальное» — разница; от сети «всего» — оценка потребления системы (процессор + видеокарты + «остальное», без мощности на заряд аккумулятора), а «остальное» — последнее измеренное от батареи. Мощность всего чипа — в подсказке у строки процессора.

### Экран (OLED)

У этого ноутбука экран OLED (Samsung Display, `SDC41AB`): подсветки нет, каждый пиксель светится сам, и **мощность зависит от того, что показано**, а не от яркости как таковой. Это подтвердил первый замер: при тёмном содержимом «остальное» при яркости 0 % и 100 % почти не различалось.

Кнопка «Измерить экран» в карточке «Компоненты» (только при работе от батареи, 1–2 минуты) показывает на весь встроенный экран **чёрное** изображение, затем **белое** при текущей яркости и **белое при 100 %**, затем всё возвращает. Результат — сколько стоит белое изображение сверх чёрного при данной яркости (между точками — линейно). Строка «Экран (OLED)» в таблице = это значение при текущей яркости × **доля белого** на экране: средняя линейная яркость субпикселей по уменьшенному снимку 128×80 (раз в 5 с, пока окно открыто; снимок нигде не сохраняется, ~5–10 мс процессора). После замера «Остальное» становится «Прочим». На большой белой площади OLED сам ограничивает яркость (ABL), поэтому оценка для смешанного содержимого приблизительная; чёрный экран (электроника панели) остаётся в «Прочем».

Помехи, найденные на практике, и как они обходятся:
- **смена яркости будит дискретную NVIDIA** (её драйвер следит за яркостью встроенного экрана; даже 1 % — около секунды в D0), а **её засыпание ещё ~6 с стоит +15 Вт** (по-видимому, сохранение видеопамяти). Поэтому фаза начинается, когда видеокарта проспала не меньше 10 с и после смены изображения прошло 4 с; не уснёт за 60 с — замер прерывается;
- **каждый ватт процессора прибавляет к «остальному» ещё ~0,75 Вт** (преобразователи питания, память): замеры, где процессор отклонился от медианы фазы больше чем на 1,5 Вт, отбрасываются;
- на время замера выключены свой опрос NVIDIA и сбор по процессам;
- если разница белого и чёрного не больше трёх стандартных ошибок, результат не сохраняется («замер ненадёжен»).

Чужие программы и службы на время замера не приостанавливаются: это требует прав администратора и может повесить приложения. Замер прерывается, если подключить зарядку, скрыть окно, нажать Esc или щёлкнуть по тестовому изображению; яркость возвращается и при выходе, а если программа упадёт посреди замера — при следующем запуске (прежняя яркость записывается заранее).

### Пробуждения NVIDIA

Каждое пробуждение дискретной видеокарты на батарее стоит несколько ватт на 10–20 с: ~11 с в D0 (+8 Вт) и ~6 с засыпания (+15 Вт); частые пробуждения — до ~8 Вт в среднем. Программа ведёт журнал: время, длительность, энергия сверх обычного уровня (медиана за 30 с до пробуждения; до 9 с после засыпания) и вероятная причина:
- **«открыли»** — процессы, которые получили контекст на NVIDIA в момент пробуждения (по счётчикам «GPU Engine»: пока видеокарта спит, раз в 10 с запоминается, у кого уже есть контекст);
- **«работа»** — процессы, загружавшие её движки;
- совпавшие события: смена яркости, подключение экрана, замер экрана;
- «неизвестно» — видеокарту опросили без нагрузки.

Сводка — кнопка «NVIDIA просыпалась N раз за час» в карточке «Компоненты», список — в окне «Пробуждения NVIDIA», журнал — `logs\gpu_wakes.csv` (колонки `start,end,seconds,cost_wh,flags,cause`; `flags` — `self`, если разбудил сам замер экрана, `unknown`, если причина не найдена; по ним работают советы, а `cause` — текст на языке интерфейса в момент записи. Журнал прежнего формата без `flags` переписывается в новый при первой записи). Пока видеокарта не спит при работе от батареи в фоне, опрос идёт раз в 2 с, чтобы короткие пробуждения не проскакивали. Сама программа видеокарту не будит (проверено: DXGI, окно WPF, чтение счётчиков и яркости) и в подозреваемые не записывается.

На процессорах Intel Core Ultra графика вынесена в отдельный кристалл, и домен PP1 может учитывать её не целиком (например, без вывода на экран и видеодекодера). Недосчёт тогда попадает в «Остальное». Проверка: от батареи дать нагрузку на встроенную графику (видео 4K, 3D в браузере) и сравнить прирост строки «Встроенная графика» с приростом батареи.

### Как не разбудить видеокарту

Любой запрос через NVML (и `nvidia-smi`) переводит спящую видеокарту из D3 в D0, а это около 8–9 Вт. Поэтому программа сначала читает состояние из диспетчера устройств (это видеокарту не будит) и обращается к NVML, только если видеокарта уже работает. В D3 записывается 0 Вт. Если при запуске видеокарта спит, NVML инициализируется позже, когда она проснётся сама.

**Кто держит видеокарту без нагрузки.** Программа может не загружать дискретную карту, но держать на ней видеопамять — и карта не уснёт (так Figma, работающая в трее после закрытия окна, держала 197 МБ и стоила ≈ 8 Вт). Замер по процессам читает и видеопамять процессов на адаптере NVIDIA (счётчики «GPU Process Memory», карту не будят): если карта не спит, а нагрузки на ней нет, её мощность делится между такими держателями по объёму памяти (System, csrss и сама программа — не в счёт). В таблице процессов у них в колонке «ГП» — «держит», в уведомлении «видеокарта не спит» — имя и объём памяти, в совете — как закрыть программу полностью или перевести её на встроенную графику.

**Не отключайте дискретную видеокарту в диспетчере устройств ради экономии.** Без драйвера её некому перевести в сон, а Windows при этом продолжает сообщать «D3». На этом ноутбуке отключённая карта прибавила +17 Вт (15,5 → 34–36 Вт). Программа распознаёт отключённую карту (состояние устройства через `CM_Get_DevNode_Status`): в строке видеокарты — «отключена — не спит», при работе от батареи — уведомление и совет, в логе — колонка `dgpu_disabled`.

Видеокарта не может уснуть, пока на неё выводится изображение. Обычно это внешний монитор, подключённый к порту, который разведён на дискретную графику. На экране это видно в строке «Экраны».

От сети общее потребление не измеряется: у адаптера нет датчика, а счётчик ACPI Power Meter на этом ноутбуке не поддерживается.

## Сессия разряда

Энергия считается двумя независимыми способами:
- **по мощности:** сумма P·Δt;
- **по остатку заряда:** убыль остатка, который ведёт контроллер батареи.

Если способы расходятся больше чем на несколько процентов, контроллер батареи плохо откалиброван. Интервалы длиннее 5 с (сон, гибернация) не учитываются.

## Формат лога

CSV, разделитель `,`, десятичная точка, кодировка UTF-8. Одна строка на замер.

| Колонка | Единицы |
|---|---|
| `time` | Локальное время, ISO 8601 |
| `power_state`, `on_ac`, `charging`, `discharging` | Флаги состояния питания |
| `capacity_mwh`, `full_mwh`, `soc_pct` | Остаток, полная ёмкость, заряд в % |
| `voltage_mv`, `rate_mw`, `current_a` | Напряжение, мощность (< 0 — разряд), ток |
| `cpu_pkg_w`, `cpu_cores_w`, `igpu_w`, `dram_w` | Мощность процессора по компонентам, Вт |
| `dgpu_w`, `dgpu_util_pct`, `dgpu_pstate` | Видеокарта NVIDIA (в D3 — 0 Вт) |
| `dgpu_dstate` | Состояние питания видеокарты: 0 — D0 (работает), 3 — D3 (спит) |
| `displays`, `displays_on_dgpu` | Подключённые экраны, из них через NVIDIA |
| `rest_w` | Остальное, Вт (только при разряде) |
| `idle_s` | Секунд без ввода с клавиатуры и мыши |
| `brightness_pct`, `screen_w` | Яркость и оценка мощности экрана (пока окно открыто и экран замерен) |

На диск лог сбрасывается раз в минуту, чтобы не будить диск каждую секунду.
